# Windowsが再起動された後にやるべきルーチン

## 0. この手順書の前提

- 読むのは、持ち主本人です。再起動の直後、画面の前にいて「次は何だっけ」と自信がなくなった時に開いてください。
- 入り口は、再起動が済んで再ログインした所です。出口は、タスクトレイに鯨がいて、常駐の物が上がっている状態です（常駐プログラムの処理、節 5）。
- やらない条件: 時間がない時は、そもそも再起動を後回しにしてください。「時間のないときにパソコンを立ち上げ直すのがおかしい」。時間がなくて焦っている時に手順を飛ばすと、後で原因の分からない不調に悩みます（やらないこと、節 6）。
- この手順書は 2026-10-20 時点の構成で書いています。道具（Obsidian・Docker・bot）が変われば手順ごと変わります。この日の構成は「この日の構成」（節 8）にあります。
- この見本では、実際にはユーザー名などが入っていた所を「持ち主」に置き換えています。固有のフォルダ名や企画名も言い換えています。
- 骨組みも小段も、実機を見ながら語った物ではありません。次に再起動した時に照らして、違う所があれば直してください。〔仮: 実機を見ずに語った〕

### 全体の流れ

五段あります。主語は持ち主です。節の番号と段の番号は同じです。

1. ログイン（節 1）
2. バックグラウンドプログラムの処理（節 2）
3. オブシディアン関連の処理（節 3）
4. ドッカーの処理（節 4）
5. 常駐プログラムの処理（節 5）

大きな流れは毎回同じです。細かい所は状況で飛んだり戻ったりします。順番の決まり:

- オブシディアンはドッカーより先に済ませてください。これは癖ではなく必須です。ドッカーの再起動手順は覚えられないので、オブシディアンのメモを開いていないとドッカーの処理が進みません（段をまたぐ組、節 7）。
- バックグラウンドの更新で bot を落としたら、常駐プログラムの処理で上げ直します。間に二段挟まるので忘れやすい所です（段をまたぐ組、節 7）。

## 1. ログイン

- 再ログインします。これ以上分かれません。

## 2. バックグラウンドプログラムの処理

注意: この段の更新で bot を落としたら、最後の常駐プログラムの処理（節 5）で上げ直すことを忘れないでください。

- 2-1. ログイン時に起動するけれど普段使っていない窓（液タブの管理プログラム・ツアーボックスの管理プログラム・スチームなど）が開いたら閉じていきます。
- 2-2. ローカル LLM 起動のために必要なバックグラウンドプログラムが起動するのを目視します。タスクトレイにアイコンが出る物と、窓として立ち上がる物があります。窓の方は、更新が来ていなければ、普段使っていない窓と同じように閉じて、タスクトレイにアイコンが残っているのを見ます。〔空欄: どのプログラムがどちらの型か〕
- 2-3. ローカル LLM 利用の常駐 bot も、ここで起動していることが多いです。これは持ち主がやることではなく、起きていることです。
- 2-4. ワンドライブやタスクトレイのアイコンが落ち着く（増えたり、アイコンが変化しなくなる）のを待ちます。
- 2-5. ローカル LLM を走らせるプログラムに更新が来ていたら、bot を落とし、バックグラウンドプログラムを更新・再起動します。更新は、窓に出ているか、タスクトレイが通知を出してきます。
  - 注意: 先に bot を落としてください。後から落として立ち上げ直しても直りますが、落とし忘れると「更新した」ということ自体を忘れて、エラーに悩むことになります。
  - 落とし忘れた時の手掛かり: bot に話しかけるとやたら時間が掛かります。bot は起動時に、規定より多くのコンテキストを準備した状態でローカル LLM を常駐させる仕様です。後からバックグラウンド側（API を担う方）が再起動すると、その準備が無かったことになるからです。
  - 時間がなくて焦っている時は、この更新は見送って構いません（やらないこと、節 6）。〔空欄: 見送った更新をいつやるか〕
- 2-6. もう一回タスクトレイを確認します。
- 済んだ合図: ワンドライブの雲アイコンが同期完了の姿で、アイコンが 15 個くらい揃っていて、数秒眺めても増えてこない。〔仮: 15 個は 2026-10-20 時点〕

## 3. オブシディアン関連の処理

注意: 焦っていると、コミュニティプラグインの設定を開いてから Git の同期を見るまで（3-2〜3-5）を丸ごと飛ばすことがあります。飛ばすと Git がオフのまま保管庫を使うことになり、気付く機会がほとんどありません（やらないこと、節 6）。

- 3-1. オブシディアンを起動します。
- 3-2. コミュニティプラグインの設定画面を開きます。コアプラグインではなく、コミュニティプラグインの方です。設定窓がオーバーサイズで、隣のモニターに少しはみ出るので、ドラッグで持ち帰って、改めて最大化ボタンで枠に収め直します。〔仮: はみ出る原因は、Obsidian 用のモニターが他の二枚より少し小さいから、かもしれない〕
- 3-3. 更新確認ボタンを押し、更新があればまとめて更新ボタンを押します。
- 3-4. オフになっているプラグインをオンに切り替えます。ほぼ確実に Git と Templater が、たまにルビ振りプラグインがオフになっています。
- 3-5. Git がファイルを同期するのを目視します。
  - 済んだ合図: オブシディアンの画面に小さな通知がポコポコ出ます。
- 3-6. 保管庫の保管庫のメモ「Dockerが起動しないときの操作」を開きます。次のドッカーの処理（節 4）で見ながら使います。

## 4. ドッカーの処理

注意: この節はオブシディアン関連の処理（節 3）を済ませてからです。そこで開いたメモが無いと、コマンドの送信が進みません（段をまたぐ組、節 7）。

- 4-1. タスクトレイの中に鯨（Docker のアイコン）がいないことを確認します。
- 4-2. ターミナル（パワーシェル）を起動します。
- 4-3. 開いてある保管庫のメモ「Dockerが起動しないときの操作」の手順に従い、ターミナルにコマンドを 3 回送信します。中身は、Docker 関連のプロセスを全部落とす、WSL をシャットダウンする、Docker Desktop を起動し直す、の三つです。UAC（管理者昇格）が出たら「はい」。〔資料: 保管庫のメモ「Dockerが起動しないときの操作」。コードさんが書き、持ち主が 2026-06-30 に保管庫に貼った。以後未編集〕〔仮: コマンドはこの手順書に写さず、メモを見る形にした〕
- 4-4. Docker デスクトップが出てくるので、各ドッカープログラムの起動を目視します。一覧に アーカイブ用のコンテナ と 保管庫検索のコンテナ が見えて、保管庫検索のコンテナ をクリックすると中に ベクトル検索の箱 と 全文検索の箱 が入っています。〔仮: 保管庫検索のコンテナ の綴りは話し手が「多分そう」。構成は 2026-10-20 時点〕
- 4-5. Docker デスクトップは一旦閉じます。開けたままだと、うっかり誤クリックでコンテナを止める可能性があるからです。
- 4-6. タスクトレイに鯨を目視します。
- 済んだ合図: タスクトレイの鯨です。この節は「鯨がいない」で始まり「鯨がいる」で終わります。
- 補足: やる所は、ターミナルの起動とコマンドの送信の二つです。他（鯨がいないことの確認・起動の目視・デスクトップを閉じる・鯨の目視）は確認で、飛ばしても害が少ないです。やる所を飛ばすと、後から保管庫の検索ができなくなっていることに気付くはずです。〔仮: 実際にそうなったことはまだない〕

## 5. 常駐プログラムの処理

注意: バックグラウンドの更新で bot を落としていたら、ここで上げ直してください。落としたことを忘れて飛ばしやすい所です。

- 5-1. ローカル LLM の bot を、ここまでで落としている場合は再起動します。bot の起動スクリプト（.ps1）を右クリックし、「PowerShell で実行」を選びます。
  - 注意: これは Windows でしか動いていません。他の常駐は出先でも代替手段がありますが、これだけは出先から直せません。
- 5-2. Discord が未起動だったり、アップデートが来ている場合は再起動します。窓が出ていなければ未起動です。アップデートが来ていると、右上に更新アイコンが出ています。〔仮: 自動起動していると思われる〕
- 5-3. クロードさんのデスクトップアプリを起動します。
- 5-4. クロードさんのアプリで「ご利用状況」を開きます。主にコードさんの使用量を確認するためです。
- 済んだ合図: ここまでで出口です。

## 6. やらないこと・飛ばしてよいこと

- 時間がない時に再起動しない。「そもそも時間のないときにパソコンを立ち上げ直すのがおかしい」。
- 時間がなくて焦っている時は、ローカル LLM のバックグラウンドの更新（節 2 の 2-5）は飛ばしてよい。事故のもとになりやすいからです。
- 焦っていても、コミュニティプラグインの更新と Git のオン（節 3 の 3-2〜3-5）は飛ばさない。飛ばすと気付く機会がほとんどありません。気付く経路は、スマホから GitHub のコミットを見に行って更新が無いことに気付くか、何かの拍子にコードさんが指摘するか、の二つだけです。スマホは普段リモートシンクで保管庫を見ているので、どちらも滅多に起きません。
- ドッカーの処理（節 4）のうち、確認の段（鯨の確認・起動の目視・デスクトップを閉じる・鯨の目視）は飛ばしても害が少ない。やる段（ターミナルの起動とコマンドの送信）は飛ばさない。
- Docker デスクトップを開けたままにしない。誤クリックでコンテナを止めないためです。

## 7. 段をまたぐ組

離れた段どうしで、片方をやったらもう片方も要る組です。

- バックグラウンドの更新で bot を落とす（節 2）⇔ 常駐プログラムの処理で bot を上げ直す（節 5）。間にオブシディアンとドッカーが挟まるので忘れます。
- オブシディアンで保管庫のメモ「Dockerが起動しないときの操作」を開く（節 3）→ ドッカーの処理でそのメモを見ながらコマンドを送る（節 4）。オブシディアンが先、ドッカーが後。順番ではなく依存です。
