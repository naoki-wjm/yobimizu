# 「呼び水」の使い方

## 0. この手順書の前提

- 読むのは、初めて「呼び水」を使う人です。誰かに残しておきたい手順などを残し、後から検索します。
- 段ごとに通る人が違います。
  - 下準備（節 1）と検索窓生成（節 4）: マニュアルの総管理者
  - 聞き取り（節 2）: マニュアルの作り手
  - マニュアル保存（節 3）: 誰でも。ただし記録を集める所（3-2）だけは作り手
  - 検索（節 5）: 検索者さん
  - 改善（節 6）: マニュアル管理者。内容が複雑に感じられたら作成者に聞き直す
- 揃っている物: GitHub にある yobimizu（「呼び水」を作るための道具一式）と、Python を動かす環境（節 1 で準備します）。聞き取りと改善には LLM を使います。
- 次にやる時に照らして、違っていたら直してください。

### 全体の流れ

六段あります。節の番号と段の番号は同じです。

1. 下準備（節 1）
2. 聞き取り（節 2）
3. マニュアル保存（節 3）
4. 検索窓生成（節 4）
5. 検索（節 5）
6. 改善（節 6）

検索の後、改善することがあれば、その結果がマニュアル保存（節 3）に戻って、そこからまた検索窓生成（節 4）、検索（節 5）とループします。

下準備（節 1）とマニュアル保存（節 3）の中には、初回だけの手順があります。〔空欄: 二回目以降の下準備はどうなるか。飛ばす時があるか〕

〔空欄: やらない条件・人に戻す所〕

## 1. 下準備

この段はマニュアルの総管理者が通ります。

- 1-1. マニュアルの置き場を決めます。
  - マニュアルのフォルダの中に、検索用の窓も、初期設定でのフィードバック用ファイル（reactions.md）も入ります。とにかく忘れにくい場所をオススメします。
  - 複数人でマニュアルを見る場合は、全員がアクセスできる場所が大前提です。
- 1-2. Python がない場合は準備しておきます。〔仮: 話し手は Python が前から入っていたので、この手順は通していない〕
  - 注意: Python の手順に慣れていない人は困りそうです。準備できなければ、後半で検索用のサイト（検索窓、節 4）が組み上がりません。〔空欄: 何が楽な入れ方か〕
- 1-3. 道具としての yobimizu をダウンロードします。ZIP でダウンロードしてくる場合と、git clone する場合があります。それぞれ手順と注意事項が違います。ダウンロードする場所（つまり道具一式の「落とし先」、「落とす場所」）は、ZIP で持ってくる分には任意の場所となります。
  - ZIP の場合:
    - GitHub のリポジトリ（企画本体を置いている場所）に Code という緑のボタンがあるので、そこを押すと、コードを持ち帰るためのメニューが開きます。
    - その最下部に Download ZIP という選択肢があるので押すと、Windows の場合はダウンロードフォルダに ZIP が入ります。
    - ZIP の中にある yobimizu-main フォルダ（yobimizu フォルダ）を、PC 再起動などで行方不明にならない任意の場所に置いておきます。〔空欄: ZIP から取り出す所〕
    - 補足: この場所は、マニュアルの置き場（1-1）とは別々に設定しても構いません。マニュアル置き場は一般に分かりやすい場所、yobimizu はマニュアルを管理する側が操作できる場所、と分けることもできます。
  - git clone の場合:
    - git clone ができる場合は、それなりの技術者とお見受けします。
    - 注意: Windows の OneDrive に代表される他の同期システムと git が喧嘩しない場所を、ターミナルなどで指定してから、企画リポを git clone してください。〔仮: yobimizu では確かめていない。yobimizu 以外のプロジェクトが git と OneDrive の競合でクラッシュした経験から〕
- 1-4. スキルとして使う場合は、登録しておきます。〔仮: 話し手は script.md を貼る使い方だったので、この手順は通していない〕〔空欄: 登録の手順〕
  - 補足: script.md を LLM に渡す使い方（聞き取り、節 2 の 2-1）なら、この手順は要りません。

順番: 1-3 が終わってからでないと 1-4 はできません。残りの二つは任意の順番です。〔仮: Python まわりに細かな設定を行う場合は、順番が変わる可能性がある〕

〔空欄: 済んだ合図〕

## 2. 聞き取り

この段はマニュアルの作り手が通ります。

- 2-1. 聞き取りを始めます。
  - 自分の使っている LLM に、スキルとして既に yobimizu-kumiage が登録されていれば、それを使えば聞き取りが始まります。
  - 登録されていない場合は、`yobimizu/yobimizu-kumiage/` 内にある script.md を LLM に渡してください。「何について教えてくれますか？」から聞き取りが始まります。
  - 注意: script.md というファイルは、別名のフォルダの中にもあります。フォルダ名を間違えると困ります。間違えるとしたらマニュアル改訂スキル（yobimizu-kaitei、節 6）との取り違えになるはずなので、最初の質問から違和感があるはずです。
- 2-2. 幾つかの段階を踏んで聞き込まれます。
  - 注意: この段が、最も時間と手間のかかる作業です。
  - 注意: LLM が、段階があるときにどんどん先走っていく可能性があります。休憩を入れたいときは、無理せず休憩を入れてください。
  - 補足: LLM との相性次第なので何とも言えませんが、なるべく賢いモデルの方が気配り上手な気がします。
- 2-3. 記録を出力してもらいます。
  - 一回で全てを終わらせるのが大変な場合など、任意のタイミングで一時中断して記録を出力できるようにしてあります。最後まで聞き込まれた後も、LLM が記録を出力します。
  - 注意: 何事にも絶対はありません。記録が出されないときは、一度 script.md に沿った記録を出すよう促してみてください。
- 済んだ合図: LLM が記録を出力します。

## 3. マニュアル保存

この段は誰がやっても結果に変わりはないので、マニュアルの総管理者が回すことも想定されます。ただし 3-2 だけは作り手が通ります。

- 3-1. 初回だけの手順です。下準備で決めた置き場（節 1 の 1-1）のフォルダの下に、records と manuals というフォルダを作ります。
- 3-2. records フォルダの中に更に新規フォルダを一つ作成し、聞き取りで出力された一つの題材についての記録（節 2 の 2-3）を、そのフォルダの中に集めます。
  - 記録は聞き取られた LLM が出力するので、それを保存できるのは、その会話を行った話し手（作り手）です。
  - フォルダ名は、マニュアルのタイトルになりそうなものを仮でつけておいて、マニュアルが確定したらそのタイトルに揃えるのが良いでしょう。
  - 注意: 初回は「どうしてもう一個フォルダが必要なんだ……」ってなるかもしれませんが、各マニュアルごとの一次記録をまとめるためですので、ご了承ください。
- 3-3. フォルダに集めた記録と `shelf/format.md` を、新規で LLM に渡して、マニュアルとしてまとめた Markdown を出力させます。
  - 補足: 今のところは、聞き取りとは別の新しい会話で渡しています。コンテキスト（LLM の脳内、もしくは作業机みたいなイメージ）を一旦リフレッシュさせることで効率化させるためです。また、この段は総管理者が回すことも想定されるからです。
- 3-4. 出力されたマニュアルを、置き場に作った manuals フォルダに保存します。

〔空欄: 済んだ合図〕

## 4. 検索窓生成

この段はマニュアルの総管理者が通ります。

- yobimizu フォルダで、右クリックなどでターミナルを開き、`python reader/build_reader.py <置き場のフォルダのパス>` を実行します。
  - 置き場のパスは、Windows の場合、置き場フォルダを選択して右クリックすると、「パスのコピー」という項目がメニュー内に出てきます。
- 注意: 置き場のパスを間違える、yobimizu フォルダ以外で実行する、が間違えやすい所です。
  - 実行した別フォルダにも `reader/build_reader.py` があると、それが動きます。その場合だけは被害が予測できません。
  - それ以外の場合は、ターミナルの画面にエラーが出されて、何も起こりません。〔仮: パスを間違えた時のエラーは、話し手は見ていない〕
  - 実例: `reader/build_reader.py` を `reader/build.py` と書き間違えて、エラーになりました。
- 今の版では、reactions.md も、存在しなければ作成されます。
- 済んだ合図: 置き場のフォルダの中に、reader.html という、検索窓として開けるページが作成されています。

## 5. 検索

この段は検索者さん向けです。

- 5-1. 検索窓（置き場/reader.html）を開きます。
- 5-2. 検索窓で、単語メインで検索します。検索窓そのものには LLM は関わらないので、なるべく単語を用いるのが良いです。
  - 出なかった時は、言葉を短くしたり変えたりして引き直します。
- 5-3. 検索結果について、結果ページの末尾のアンケートにボタンで答えます。
  - 出なかった時は、「出なかった」とコメント済みのアンケート結果が左下に出てきます。
- 5-4. 答えを置き場/reactions.md の末尾に 1 行で付け足し、改行せずに末尾にコメントも足して保存します。
- 補足: 5-3 と 5-4 は面倒だと思いますが、マニュアルの改善（節 6）につながる場合があるため、余裕があれば是非お願いします。

〔空欄: 済んだ合図〕

## 6. 改善

この段はマニュアル管理者が通ります。ちょっとした改善ならマニュアル管理者で可能ですが、内容が複雑に感じられたら、マニュアル作成者に聞き直す必要もあるでしょう。

- 6-1. reactions.md の行が増えてきたと感じたら、開始のタイミングです。
- 6-2. yobimizu-kaitei のスキル、もしくは `yobimizu-kaitei/script.md` を LLM に渡します。
- 6-3. reactions.md と、そこで言及されていたと判断されるマニュアルを、LLM に追加で渡します。
- 6-4. LLM からの聞き取りに答えていくことで、マニュアルの改訂が行われます。
- 6-5. 最終的に、改訂したマニュアルと、対応を記録した reactions.md が出力されるので、元のファイルに上書きします。
  - 改訂用の聞き取りのファイルも出力された時は、records の中の対応フォルダ（マニュアル保存、節 3 の 3-2）に追加保存します。実際に一つだけのマニュアルで回した場合に出力されたことがあり、三つのマニュアルを渡した時は出てきませんでした。
- 6-6. マニュアル本文の変更があった場合は、yobimizu フォルダで `python reader/build_reader.py <置き場のフォルダのパス>` を再実行します（検索窓生成、節 4）。
  - 注意: うっかりマニュアル検索ページの再生成を忘れそうです。
  - 済んだ合図: reader.html が上書きされます。
