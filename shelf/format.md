# 呼び水 — 置き場の型（マニュアルの書式・ペライチ）

聞き取りの記録からマニュアル本文を書く時と、出来たマニュアルを置く時の決まりです。台本（`yobimizu-kumiage/script.md`）の「芯 4 — 出力」を、置き場の側から細かくした物です。これを読んでいるあなた（LLM）が本文を書く時は、この紙だけ読めば書けます（台本の芯 4 と重なる所は、どちらの紙もそれだけで動くための重なりです）。

決まりは三つの都合でできています。**人が読む**（検索から節に直接飛び込んで、前を読まずに分かる）・**機械が拾う**（サーバーなしの検索窓が、ただのコードで索引を作れる）・**後で直せる**（改訂しても参照が切れない）。迷ったら人が読む都合を優先します。

## 1. フォルダ構成

~~~
<置き場>/
  manuals/       … マニュアル本文。1 ファイル＝1 題材
    <題名>.md
  records/       … 聞き取りの記録。1 ファイル＝1 回（弾）
    <題名>/<日付>-<弾>.md
  reactions.md   … 引いた答えへの反応（追記だけ。節 7）
  reader.html    … 読む側の 1 枚（生成物。手で直さない）
~~~

- 置き場は使う人が決めます。フォルダ名も変えてよく、検索窓を作るコードには置き場のパスを渡すだけです
- **ファイル＝題材、節＝索引の単位**。ファイルは人が開く単位、節は検索が落とす単位です
- 索引が読むのは `manuals/` の中だけです。記録は索引に入れません。記録には言い間違い・聞き手の整理・未確認がそのまま残っていて、検索に出すと答えに混ざるからです。記録へは本文の末尾から辿ります（節 5）

## 2. 設定欄（本文の冒頭）

台本の 6 項目に、3 つ足した 9 項目です。

~~~
---
title: 題名（話し手の言葉から。ファイル名と同じ）
created: 2026-01-01
updated: 2026-01-01
summary: 一文の要約
aliases: [別名, 読み手の言い方, 画面の文字]
questions:
  - こう聞かれたらこれを出す → 節 3
  - 想定質問は質問文のまま（答える節が一つに決まらなければ矢印なし）
readers: [誰が読むか]
series: 一段大きいまとまりの名前
related: [似ているけど別の物の題名]
---
~~~

| 項目 | 書き方 | 検索窓での使い方 |
|---|---|---|
| title | 題名。**話し手の言葉のまま。整えない**（整えた言い方は aliases へ）。ファイル名と一致させる | 結果の見出し。参照の宛先（節 5） |
| created | 初版の日。改訂しても変えない | 「いつの話か」を結果に添える |
| updated | 最後に直した日。無ければ created を使う | 同上。締めの札「日付を書かないと嘘になる所」の受け皿 |
| summary | 一文。本文を開く前の当たり | 結果の一行目 |
| aliases | 採らなかった言い方。言い換えずそのまま | 検索語に当てる。title と同じ重さ |
| questions | 想定質問。質問文のまま。10 を超えるなら `- ` の箇条書きで。**各行の末尾に「→ 節 N」で答える節を書いてよい**（任意。まとめの回で書く人は、どの質問にどの節が答えるかを知っている） | 検索語に当てる。「→ 節 N」があればその節の一件に、無ければファイルの入口（節 0）に当たる |
| readers | 読み手。複数可。LLM も人も | 結果の絞り込み |
| series | 一段大きいまとまり（上位の名前）。無ければ省く | 結果をまとまりで束ねる |
| related | 似ているけど別の物の題名。無ければ省く | 結果の末尾に「似ているけど別」を出す |

- series と related は、締めの札「一段大きいまとまりは？」「似ているけど別の物は？」の答えの置き場です。本文の節に書くだけでは機械で束ねられません
- 入れない物: 型（手順／仕組み／心得）は混ざる題材が多いので項目にしません。状態（下書きなど）は空欄の節（節 3）で分かります。話し手の名前は、公開の可能性があるので既定にしません
- **上の 9 項目以外は索引が無視します**。使う人は好きな項目を足してよい（例: Obsidian の `tags:`・`modified:`）。既定の項目の意味は変えないでください
- 書き方の縛り: 1 行 1 項目。値は 1 行。一覧は `[a, b]` か `- ` の箇条書き。項目の中に `,` を使わない（読点は `、`）

## 3. 本文の決まり

### 節と番号

- `# 題名` を 1 つ。節は `## 番号. 見出し`。節の中の `###` は使ってよいが、索引の単位にはなりません
- **節の粒度**: 検索から直接飛び込まれて、前の節を読まずに分かる大きさ。手順なら一つの段、仕組みなら一つの部品、心得なら一つの教え
- **番号は名前であって順番ではなく、改訂しても変えません**。読む側の記録と反応が「題名＋節番号」でつながる前提です
  - 足す時: 未使用の次の番号。並びは番号順でなくてよい（途中に挟んでよい）
  - 消す時: 見出しを残して「（廃止。節 N へ）」の一行。番号を使い回さない
  - 割る時: 元の番号は片方が引き継ぎ、もう片方は新番号
- 手順の型では、**聞き取りの段 N ＝ 本文の節 N** に揃えます。聞き取りで呼んでいた「2-5」が本文で「3-5」にならないためです。そのために「全体の流れ」は節 0 の中に入れます

### 節 0 は前提（番号固定・推奨）

- 誰が読むか・いつ読むか・入口と出口・揃っている物（環境・道具・権限）・やらない条件（人に戻す所）
- 読み手に LLM が入る時は節 0 を必須にし、「分からなければ止まって聞く」の一文を入れます（台本 芯 5）。読み手が本人なら「次にやる時に照らして直す」でよい
- **全体の流れ**（段の一覧・順番の揺れ・飛ばす時・戻る時・段をまたぐ依存）は、節 0 の中に `###` で書きます

### 最後の節は「空欄」（見出しの語を固定）

- 聞き取りで埋まらなかった所の一覧。各行に、どの節の事かを見出しの言葉と節番号で添える。**聞けなかった所だけ**。答えの出ている物は書かない
- 話し手の「後で埋める／空けたまま」の答えもここに
- **この節の中では〔仮〕〔空欄〕の印を使わない**。印は効く節の本文に置く（読む側は印を節ごとに数える。ここに付け直すと二重に数え、本文から外すと「この節に空欄あり」が出ない）

### 手順の節の中の順

注意 → 指示 → 補足 → 済んだ合図。行頭の札で書きます。

- `注意: …` その節で効く物だけ。節をまたいだら繰り返す（読み手はどこから読むか分からない）。同じ節の中では繰り返さない。短く
- `済んだ合図: …` 何を見れば終わったと分かるか
- `やらない: …` 節 0 にまとめず、効く節に置く時
- 札は、記録にある時だけ。無い段に作らない（「ログインしたら次へ」のような中身の無い合図を足さない）。合図が聞けていなければ `〔空欄: 済んだ合図〕`
- 解説（なぜ）は手順の流れを止めず、節の後ろか別の節に。一文に一つのこと。三つ以上は箇条書き。読み手一人に向けて、能動で
- 手順の節の中の小段は、行頭に `- N-M.`（節 N の M 番目）を置いてよい（任意。索引は拾いません。人と反応の行が指すための名前です）
- 読み手がしない段（相手・機械・他人が動く段）は、「これはあなたがやることではなく、起きていることです」のように、そう書いて短く済ませてよい

### 文中の参照

**見出しの言葉を先に、番号は括弧で後ろ**。「やらないこと（節 6）」「設定を開いてから同期を見るまで（3-2〜3-5）」。数字だけ（「3-5 で落とした物を 6-1 で」「（節 7）」）だと、読み手が迷子になります。機械が拾う形は括弧の中に残るので壊れません。

### 仮と空欄の印（形を固定）

- `〔仮: 理由〕` … 話し手が自信なく言った・確かめていない所
- `〔空欄: 何が無いか〕` … 聞けなかった・出てこなかった所
- 理由が無い時も `〔仮〕` `〔空欄〕`。読む側が節ごとに「仮あり・空欄あり」を出せます

### 足さない・言い換えない（台本 芯 1 の 4・5 と同じ。この紙だけで動くために写す）

- 記録に無い事実・推測・一般論を本文に足さない。足りない所は `〔空欄: 〕` のまま残す
- 話し手の言葉を本文で言い換えない。その言葉が検索の手掛かりです。製品名・画面の文字・話し手の呼び方を、英字に直したり正式名に替えたりしない
- 正式な言い方を決めた時は、初出で「正式（話し手の言い方）」と並記し、話し手の言い方は aliases にも入れる
- 文体（です・ます、常体）は決めない。置き場ごと、題材ごとに、読み手が気になった時に直す

### 任意の節（型が合う時だけ）

- 「やらないこと」… やらない条件・飛ばしてよい所をまとめて見せる時（節ごとの `やらない:` と両方あってよい）
- 「段をまたぐ組」… 離れた節どうしの依存・対。片方をやったらもう片方も要る物
- 「この日の構成」… 使っている道具の一覧と日付。道具に依存する題材で「日付が要る所が全部」の時、節ごとに日付を打つ代わりに置く。updated は本文を直した日に使う
- 「似ているけど別のもの」… related の説明。まだ書かれていない物は related に入れず、節の中に「（未作成）」

## 4. 出どころの印

出どころ（誰が言ったか）と確かさ（どこまで固まったか）は別の物です。確かさの印は節 3 の〔仮〕〔空欄〕。出どころの印は次の通り。

| 印 | 意味 | 記録での形 |
|---|---|---|
| （印なし） | 話し手が自分でやった・確かめた | 引用そのまま |
| 〔伝聞〕 | 話し手が人から聞いただけ | 引用の末尾に付ける |
| 〔資料: 名前〕 | 見せてもらった物・既にあった文章から | 「ここは誰が書きましたか」を聞いてから付ける |
| 〔 〕 | 聞き手の整理・推測 | 〔 〕で囲む。推測は末尾に「？ 未確認」 |

- 出どころの印は**記録では必須、本文では任意**。本文の既定は、書き手が責任を負う一つの声です。本文に残すのは話し手が望んだ時だけ
- 本文に出す時は文末に `〔伝聞〕` `〔資料: 名前〕`。聞き手の〔 〕は本文に出さない（確かめて印なしにするか、〔仮〕にする）
- 印は全部 `〔…〕` の形。索引が数えるのは〔仮〕〔空欄〕だけで、他は人向けです

## 5. 参照・シリーズ・似て非なる物

- 同じマニュアルの中: 見出しの言葉を添えて「（やらないこと、節 7）」。読む側は「節 7」をリンクにできます
- 別のマニュアルへ: `[[題名]]`。節を指す時は「[[題名]] の節 3」と言葉で
- 宛先は題名＝ファイル名。題名を変えると参照が切れるので、変える時は aliases に旧題名を残す。番号の ID は足さない
- 記録への参照: 本文の末尾に「記録: [[記録のファイル名]]…」の一行。記録から本文へは、記録の冒頭に `[[題名]]`
- シリーズ: `series:` に名前。シリーズ自体の案内が要る時は、同じ名前のマニュアルを 1 本書く（節 0 に子の一覧）。フォルダにはしない（一本が二つのシリーズに入れなくなる）
- 似て非なる物: `related:` に題名、違いは節「似ているけど別のもの」に一言

## 6. 機械が拾う形（書く時に壊さない約束）

検索窓を作るコードは、次の形だけを頼りに索引を作ります。ここを崩さなければ、他は自由です。

| 拾う物 | どこ | 形 |
|---|---|---|
| 設定欄 | 1 行目の `---` から次の `---` まで | `key: value` 1 行 1 項目。一覧は `[a, b]` か `- ` 行。知らない key は無視 |
| 節 | `## 番号. 見出し` の行 | 番号・見出し・次の `## ` までの本文。`###` は本文の一部 |
| 題名 | 設定欄の title | `# ` の行は使わない |
| 仮・空欄 | `〔仮` `〔空欄` で始まる印 | 節ごとに数える |
| 札 | 行頭（`- ` の後も可）の `注意:` `済んだ合図:` `やらない:` | 読む側で目立たせるだけ |
| 節内参照 | 「節 N」 | 同じファイルの節へ |
| 外部参照 | `[[題名]]` | 題名→ファイル |
| 反応 | `reactions.md` の行（節 7） | 題名と節番号で本文に結ぶ |

- 索引の 1 件＝1 節。各件に、そのファイルの設定欄（summary・readers・series・updated）を写して持たせます。**title・aliases・「→ 節 N」の無い questions はファイルの入口（節 0 の件）だけに持たせ、「→ 節 N」付きの questions はその節の件に持たせます**（ファイル単位の言葉を全部の節に写すと、一語で同じファイルの全節が同じ強さで当たり、どの節が答えか分からなくなる）
- 文字コードは UTF-8（BOM があっても落ちない）。改行は LF でも CRLF でも

## 7. 反応の行（reactions.md）

読む側で引いた答えに、一言を返す所です。検索窓が 1 行の文字列を出し、人がコピーして `reactions.md` の末尾に貼ります（サーバーなしの帰り道）。

~~~
- 2026-01-05 | 検索語 | 題名 | 節 3 | 部分的 | 待つ間に何をするか書いてなかった
- 2026-01-06 | 検索語 | 題名 | 節 4 の 4-1 | 役に立った |
- 2026-01-07 | 検索語 |  |  |  | 出なかった
~~~

- 区切りは ` | `。順に: 日付／検索語／題名／節（「節 N」か「節 N の N-M」か空）／反応／一言
- 反応は 役に立った／部分的／見当違い／渡した の四つ。「渡した」は、人に渡す時の一言をここに残す用
- 出なかった検索語は、検索語だけ埋めて他を空にします。見当違いが別名の不足なら、引いた語が要るからです
- 見直しの合図: 同じ題名・節番号に「部分的」「見当違い」が溜まった所から直す。引かれない節は直さない
- 改訂で本文を直したら、空欄の節から消す・〔仮〕を外す・updated を直す。番号は触らない。履歴は置き場の仕組み（git・エディタの履歴）に任せ、書式では持たない

## 8. 記録の書式（records/）

聞き取りの記録は、回（弾）ごとに 1 ファイルです。台本の芯 4 の 1 を、置き場の側から少し細かくした物です。

- 冒頭に: 日付・話し手・聞き手・題材（本文が出来ていれば `[[題名]]`）・弾・凡例の一行（「引用は話し手の言葉そのまま。〔 〕は聞き手の整理。推測には『？ 未確認』」）
- 問いの順に、問いを見出しか太字で置き、答えは引用（`> `）で話し手の言葉のまま
- 聞き手の整理は〔 〕で分ける。出どころの印（節 4）は記録では必須
- 語りに出た言葉のうち、別名・読み手の言い方・画面の文字になりそうな物は、一覧にして〔 〕で残してよい（本文の aliases の材料）
- 末尾に「空欄（次の回で聞く候補）」の一覧
- 記録には設定欄を付けなくてよい。付けても索引は読まない

## 9. 渡し方と確かめ方

台本の芯 4 と同じ決まりです。本文を書くあなたが台本を読んでいない時のために、ここにも置きます。

### 渡し方

- 置き場は話し手が決めます。最初か最後に一度だけ「どこに置きますか？」と聞く。答えがなければ渡すだけ
- 記録も本文も、**必ず次のどちらかで渡す。会話の本文に直書きしない**
  - ファイルで渡せる環境ならファイルで。ファイル名は題名（節 2 の title）と同じ
  - 渡せない環境なら、全文を一つのコードブロックに入れる。外側の囲いは `~~~` にする（中に ``` のコードブロックがあっても閉じない）。話し手には「回答全体のコピーではなく、ブロック右上のコピーボタンで」と、保存する時のファイル名（＝題名）を添える

### わかりやすさの確認（できれば）

- 出来た本文を、想定読者の一人に読んでもらい、自分の言葉で言い換えてもらう。言い換えがずれた所・詰まった所が直す所
- 読んでくれる人がいなければ、あなたが初めての人のつもりで読み、分からない所を `〔空欄: 〕` にして話し手に戻す。埋めて進まない
- 話し手に読み直してもらう時は、聞き手が書き足した言葉（話し手が言っていない「終わり」「必ず」の類）が実態より重くなっていないかを特に見てもらう
