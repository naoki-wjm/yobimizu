# 呼び水 — 読む側の落書き（画面の絵・一枚）

`reader/spec.md` の 3〜5 節を、見本一本目（`shelf/example/`）の中身で描いた物です。文字だけの絵なので、幅や色は作る時に決めます。例に使う検索語は「どこに作る」。

## 一. 開いた直後

~~~
┌──────────────────────────────────────────────────────────────┐
│ 呼び水 — 置き場の検索                       索引: 2026-10-28  │
│                                                              │
│  ┌──────────────────────────────────────────────┐ ┌──────┐   │
│  │ 何を調べますか                               │ │ 引く │   │
│  └──────────────────────────────────────────────┘ └──────┘   │
│  読み手: [全部] [統括担当コードさん] [企画担当コードさん]     │
│  まとまり: [全部]                                            │
│                                                              │
│  この置き場: 題名 1 本・節 11・〔仮〕3・〔空欄〕4              │
│  例: 企画フォルダをどこに作るか／雛形はどこ／持ち込み書        │
└──────────────────────────────────────────────────────────────┘
~~~

- 「例:」は questions から無作為に三つ。何を聞けるかの当たり
- 「索引:」は作った日。古い索引で引いている事に気付けるように

## 二. 「どこに作る」で引いた

~~~
┌──────────────────────────────────────────────────────────────┐
│  ┌──────────────────────────────────────────────┐ ┌──────┐   │
│  │ どこに作る                                   │ │ 引く │   │
│  └──────────────────────────────────────────────┘ └──────┘   │
│  読み手: [全部] [統括担当コードさん] [企画担当コードさん]     │
│                                                              │
│  3 件                                                        │
│                                                              │
│  ▸ コードさんと新しい企画を立ち上げる時の流れ                 │
│    › 7. 企画フォルダの置き場所の決め方                        │
│    持ち主の頭の中で育ったネタが、統括担当コードさんの検討を経て │
│    企画フォルダになり、企画担当コードさんが走り出すまでの四段。 │
│    …                                                         │
│    読み手: 統括担当コードさん                                 │
│    想定質問「企画フォルダをどこに作るか」（→ 節 7）で当たり     │
│                                                              │
│  ▸ コードさんと新しい企画を立ち上げる時の流れ                 │
│    › 3. 企画として立ち上げるために統括担当コードさんが下準備を │
│    （同じ summary）                                           │
│    〔仮〕1 ・ 注意あり ・ 済んだ合図あり                       │
│    本文「…企画用のフォルダを…作成します」で当たり             │
│                                                              │
│  ▸ コードさんと新しい企画を立ち上げる時の流れ                 │
│    › 5. やらないこと                                          │
│    本文「…置き場所の決め方（節 7）を見ずに作らない」で当たり   │
│                                                              │
└──────────────────────────────────────────────────────────────┘
~~~

- 一件は四行（題名 › 節／summary／札／当たった所）。同じ題名が続く時は題名を薄くしてよい
- 節 7 が一番上に来るのは、設定欄の想定質問に「→ 節 7」の宛先が書いてあるから。宛先の無い想定質問・題名・別名で当たった時は、下の「入口」の形になる
- 本文だけで当たった物は下に、数を抑える（spec 9 節の未決）

## 二の二. 別名で当たった時（入口の形）

~~~
│  ▸ 入口  コードさんと新しい企画を立ち上げる時の流れ › 0. 前提  │
│    別名「二枚組」で当たり                                      │
│      ├ › 3. 統括担当コードさんが下準備をし… 本文「二枚」で当たり │
│      └ › 9. この日の構成  本文「二枚組」で当たり                 │
~~~

- ファイル単位の言葉（題名・別名・宛先なしの想定質問）で当たった時は、節 0 を「入口」として一件出し、同じファイルで節として当たった物をぶら下げる。入口を開くと節 0 の前提と全体の流れ

## 三. 一件を開いた

~~~
┌──────────────────────────────────────────────────────────────┐
│  ▾ コードさんと新しい企画を立ち上げる時の流れ                 │
│    › 7. 企画フォルダの置き場所の決め方                        │
│                                                              │
│    企画フォルダを作る段（節 3 の 3-3）で使う物差しです。企画の │
│    性質で三つに分かれます。この分け方は、2026-10-28 の聞き取り │
│    で初めて文章になりました。                                 │
│                                                              │
│    • 最終産物だけでなく途中経過を見ることも必要そうな物、プロ │
│      グラムが絡む物、継続的なお手入れの続く物は、統括担当コー │
│      ドさんのすぐ下に入れて、GitHub でバックアップします。     │
│    • その中でも、別の端末で常時起動する物は、その端末用のフォ │
│      ルダがあるので、その下に入れます。                       │
│    • 電子書籍系やスライド作りなど…OneDrive の中に…GitHub には │
│      入れません。                                             │
│                                                              │
│    PROJECTS.md の5分類とは似ているけど別の物です（似ているけど │
│    別のもの、節 8）。                              ← リンク    │
│                                                              │
│    ──────────────────────────────────────────                │
│    作成 2026-10-28 ／ 更新 2026-10-28                          │
│    似ているけど別: （related なし）                            │
│    記録: 2026-10-28-第二弾の残り・第三弾・締め ほか 5 本        │
│                                                              │
│    この答えは:  [役に立った] [部分的] [見当違い] [渡した]      │
└──────────────────────────────────────────────────────────────┘
~~~

- 「節 3 の 3-3」「節 8」は同じファイルの節へ飛ぶ。飛んだ先も同じ形で開く
- 〔仮〕〔空欄〕が本文にあれば色を変える。`注意:` `済んだ合図:` `やらない:` は行頭を太く
- 記録はファイル名を見せるだけ。読む側からは開かない

## 四. ボタンを押した

~~~
┌──────────────────────────────────────────────────────────────┐
│    この答えは:  [役に立った] [部分的] [見当違い] [渡した]      │
│                                                              │
│    ┌────────────────────────────────────────────────────┐    │
│    │ - 2026-10-28 | どこに作る | コードさんと新しい企画を │    │
│    │   立ち上げる時の流れ | 節 7 | 部分的 |               │    │
│    └────────────────────────────────────────────────────┘    │
│    コピーしました。reactions.md の末尾に貼って、一言を足して │
│    ください。                                                │
└──────────────────────────────────────────────────────────────┘
~~~

- 一言の欄は画面に置かない。貼った後に手で足す
- 同じ節で二度押したら、一行を作り直すだけ（溜めない。溜めるのは出来事の記録の段で）

## 五. 出なかった

~~~
┌──────────────────────────────────────────────────────────────┐
│  ┌──────────────────────────────────────────────┐ ┌──────┐   │
│  │ 雛形のパス                                   │ │ 引く │   │
│  └──────────────────────────────────────────────┘ └──────┘   │
│                                                              │
│  出ませんでした。                                            │
│                                                              │
│  言葉を変えて引くか、この一行を reactions.md に貼ってくださ │
│  い。出なかった言葉は、別名を足す一番はっきりした合図です。   │
│                                                              │
│    ┌────────────────────────────────────────────────────┐    │
│    │ - 2026-10-28 | 雛形のパス |  |  |  | 出なかった      │    │
│    └────────────────────────────────────────────────────┘    │
│    [コピー]                                                  │
└──────────────────────────────────────────────────────────────┘
~~~

- 近い物を無理に出さない。「出なかった」が集まる方が、直す所がはっきりする

## 六. 絵にしていない物

- 出来事の記録（spec 6 節）。本体が動いてから
- 読み手・まとまりのチップを押した後の絞り込みの見え方（件数が減るだけ）
- スマホの幅。一枚 HTML なので、縦一列に落ちれば足りる
