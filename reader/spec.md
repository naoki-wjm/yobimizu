# 呼び水 — 読む側の仕様（ペライチ）

置き場（`shelf/format.md` の型で書かれたマニュアルの集まり）から、検索で節を引くための一枚 HTML と、それを作るコードの決まりです。2026-10-28 に、見本一本目（`shelf/example/`）を手元に置いて書きました。コードは 11/2 から。この紙は設計図で、決定ではなく案の所には印を付けています。📐 ほぼ仕様／🔬 後日詰める／💤 眠らせる。

## 0. 前提（動かない決まり）

- **サーバーなし**。出来た HTML をファイルのまま（`file://`）ブラウザで開いて動く。ネットにつながっていなくても動く（外部の CDN を読みに行かない）
- **重い処理は書く時に一回だけ**。読む時は、埋め込まれた索引をブラウザの中で引くだけ。LLM は読む側にいない
- **索引を作るのはただのコード**。標準ライブラリだけの一本。置き場のパスを渡すと `reader.html` を一枚吐く。置き場のパスは決め打ちしない
- 索引が読む形は `shelf/format.md` の 6 節だけ。本文を書く人は 6 節を守れば、この紙を読まなくてよい
- 反応の帰り道は `reactions.md` への一行追記（format.md 7 節）。読む側は一行の文字列を作って渡すだけで、書き込まない

## 1. 部品は二つ 📐

| 部品 | 何をする | 入力 → 出力 |
|---|---|---|
| 索引を作るコード | `manuals/` を読んで、節ごとの一件を集め、雛形の HTML に埋めて一枚にする | 置き場のパス → `<置き場>/reader.html` |
| 一枚 HTML（読む側） | 埋め込まれた索引を引いて、結果を見せ、反応の一行を作る | 検索語 → 節の一覧と本文、反応の一行 |

- 索引を作るコードは、置き場の `records/` を読まない（記録は索引に入れない。format.md 1 節）
- `reader.html` は生成物。手で直さない。直したければ雛形かコードを直して作り直す

## 2. 索引の一件（format.md 6 節を写した形）📐

一件＝一節。ただし、ファイル単位の言葉（title・aliases・宛先なしの questions）は**ファイルの入口＝節 0 の件だけ**に持たせ、「→ 節 N」の宛先が付いた questions は**その節の件**に持たせる。summary・readers・series・updated は各件に写す（検索窓がファイルを開き直さずに済むように）。全部の節にファイルの言葉を写すと、一語で同じファイルの全節が同じ強さで当たり、どの節が答えか分からなくなる（10-28 チャッピーの指摘で直した）。

| 欄 | 元 | 使い道 |
|---|---|---|
| 題名 | 設定欄の title | 見出し・参照の宛先・反応の一行 |
| 節番号・見出し | `## 番号. 見出し` の行 | 見出し・反応の一行・「節 N」の参照先 |
| 本文 | 次の `## ` までの Markdown そのまま | 開いた時に描く。検索の弱い当て先 |
| summary / readers / series / related / created / updated | 設定欄（各件に写す） | 絞り込み・束ね・「いつの話か」 |
| title / aliases / 宛先なしの questions | 設定欄（入口＝節 0 の件だけ） | ファイルの当たり。結果では「入口」として出す |
| 「→ 節 N」付きの questions | 設定欄（その節の件） | 節の当たり。一番強い |
| 仮の数・空欄の数 | 本文中の `〔仮` `〔空欄` を数える | 結果の札 |
| 札 | 行頭の `注意:` `済んだ合図:` `やらない:` | 結果の札と、開いた時の目立たせ |
| 参照 | 本文中の「節 N」と `[[題名]]` | 開いた時のリンク |
| 記録 | 本文末尾の「記録: [[…]]」の行 | 開いた時の「記録へ」 |

- 節 0（前提）も、最後の「空欄」の節も、一件として入れる。「空欄」で検索すると、埋まっていない所が一覧で出る（これは狙いどおりの副作用）
- ただし〔仮〕〔空欄〕の数は、「空欄」の節では数えない。空欄の節の行に印を付け直す書き手がいて、本文の印と二重になる（10-28 の他社まとめ 01 で出た）
- 設定欄の読み方は format.md 2 節の縛り（1 行 1 項目・値は 1 行・一覧は `[a, b]` か `- ` 行）に甘える。YAML の全部は読まない。知らない項目は捨てる
- 文字コードは UTF-8（BOM があっても落ちない）。改行は LF でも CRLF でも

## 3. 検索（何を入れたら何が出るか）📐

- 入力は一つの窓。空白で区切ると AND
- 日本語は分かち書きしないので、**部分一致**で当てる。当てる前に、全角英数を半角に、英字を小文字に揃える。ひらがなとカタカナの揃えは 🔬（やると「おぶしでぃあん」で Obsidian が出ないのは変わらないので、効きが薄いかもしれない）
- 当てる先と重さ（強い順）: 宛先付きの想定質問（節の当たり）＞ 題名・aliases・宛先なしの想定質問（ファイルの当たり＝入口）＞ 節の見出し ＞ summary ＞ 本文。重さの数値は 🔬（まず「どこで当たったか」を結果に出して、数値は使いながら決める）
- **二段で見せる**: ファイルで当たった物は、そのファイルの入口（節 0）を一件として出し、同じファイルで節として当たった物をその下にぶら下げる。節だけで当たった物（宛先付きの質問・見出し・本文）は、入口なしでも出す
- 当たった所を結果に書く。「別名『二枚組』で当たり」「想定質問『企画フォルダをどこに作るか』で当たり」。読み手は、自分の言葉がどこに拾われたかを知ると、次から言葉を選べる
- 絞り込み: readers（読み手）と series をチップで。既定は全部
- 並び: 重さの順。同じ重さなら updated が新しい順
- **何も出なかった時**: 「出なかった」とだけ言い、反応の一行を検索語だけ埋めた形で出す（format.md 7 節の三行目の形）。無理に近い物を出さない。出なかった語こそ、別名の不足を直す一番はっきりした合図（構想メモ）

## 4. 結果一件の形（見本一本目で描いた）📐

一覧では一件を四行で見せる。ファイルで当たった時は、その上に「入口」の行が付く。開くと本文。落書きは `reader/sketch.md`。

1. **題名 › 節番号. 見出し**（例: コードさんと新しい企画を立ち上げる時の流れ › 7. 企画フォルダの置き場所の決め方）
2. **summary**（ファイルの一文。節ではなくファイルの当たりなので、同じファイルの節が並ぶと同じ文が並ぶ。それでよい。別の題名に移った所で文が変わるのが見える）
3. **札**: 〔仮〕n・〔空欄〕n・注意あり・済んだ合図あり・やらないあり。数が 0 なら出さない。readers を一つ添える
4. **当たった所**: 「想定質問『〇〇』（→ 節 7）で当たり」「別名『〇〇』で当たり（入口）」「本文『…』で当たり」など

開いた一件には、本文の他に次を付ける。

- 文中の「節 N」は同じファイルの節へ飛ぶリンク、`[[題名]]` は別のファイルの節 0 へ飛ぶリンク。無い題名なら「（未作成）」と見せてリンクにしない
- 〔仮〕〔空欄〕は本文の中で色を変える。札（`注意:` など）は行頭を太く
- 末尾に: series（同じまとまりの他の題名）・related（似ているけど別）・記録へ（記録のファイル名。読む側からは開かない。ファイル名を見せるだけ）・created と updated
- 反応: 役に立った／部分的／見当違い／渡した の四つのボタン。押すと一行を作ってクリップボードへ（5 節）

## 5. 反応の一行（帰り道）📐

- 形は format.md 7 節のまま: `- 日付 | 検索語 | 題名 | 節 N | 反応 | 一言`
- 画面でボタンを押す → 一行をクリップボードへ → 人が `reactions.md` の末尾に貼る。一言は貼った後に手で足す（画面に入力欄は置かない。置くと「書き込めない」の説明が要る）
- 「節 N の N-M」まで指したい時は、本文中の `- N-M.` の行をクリックして選べるようにする 🔬（まずは節まで）
- 出なかった時は、検索語だけの一行を同じボタンで

## 6. 出来事の記録（本体の後）🔬

構想メモ `2026-10-17-01-03` の形（検索ごとの番号・端末の番号・誰が・出した節・開いた節・答え）。本体が動いてから、端末のブラウザ保存に溜めて「書き出す」ボタンでファイルに。`file://` で開いた時のブラウザ保存の挙動は実物で確かめてから決める。環境情報（端末名・パス）は記録に入れない。間に合わなくても本体は困らない

## 7. 技術の縛りと答え 📐

| 縛り | 答え |
|---|---|
| `file://` では別置きの JSON を fetch で読めない | 索引を HTML の中に `<script type="application/json">` で埋める。一枚で完結 |
| 外部の CDN を読まない | Markdown の描画は自前の最小限（見出し・箇条書き・強調・コード・表・`[[ ]]`・「節 N」・〔 〕の色）。ライブラリを使うなら同梱して HTML に埋める 🔬 |
| 索引を作る側は標準ライブラリだけ | 設定欄の読み取りは 2 節の縛りに頼った自前の読み方。Markdown の解析は `## ` と行頭の札だけ |
| 大きさ | 見本一本目は本文 26KB。本文が百本でも数 MB で、一枚 HTML として開ける範囲 |
| 置き場が複数 | 一枚＝一置き場。複数を束ねるのは置き場の側で `manuals/` に集めるか、別々の `reader.html` 🔬 |
| 文字と改行 | UTF-8（BOM 可）、LF/CRLF 両方 |

## 8. 止まってよい所（11/2 からの順）📐

1. 索引を作るコード（置き場 → 一件の一覧を JSON で吐く所まで。HTML なしで検品できる）
2. 一枚 HTML: 検索と一覧と開く（ここまでが本体）
3. 反応の一行のボタン
4. 出来事の記録（6 節）
5. 三つのボタンを出来事に乗せる

1 と 2 が動けば、見本一本目で「どこに作る」と引いて節 7 と 3-3 が出る所までを雑記で見せられる。3 以降は余裕があれば。

## 9. 決めていないこと（🔬 の一覧）

- 重さの数値と、本文だけで当たった件を一覧に出すかどうか（出すなら一番下に、数を抑えて）
- 空白で区切った時に AND か OR か（コードさんの推しは OR で、当たった語の数で並べ、外れた語を見せる。外れた語が別名の不足の合図になる）
- ひらがな・カタカナの揃え
- Markdown の描画の範囲（表を描くか、`~~~` の中をそのまま見せるか）
- 「節 N の N-M」の反応
- 「いつの話か」の見せ方（updated だけか、created も並べるか）
- 置き場が複数の時
- 言語またぎ（aliases が翻訳で効かない）は今は追わない（10-20 わーさん）
